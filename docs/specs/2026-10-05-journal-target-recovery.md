# 目标投资复盘在途进程恢复

仅使用标记复盘验收账户、新建一个单笔 AI 解读。保留研究默认、旧报告、三个受保护账本与全部卷。开始前确认精确 Compose 项目、数据库 owner、Server/Worker/数据库容器身份，无其他在途研究任务，也无活动构建。

正式升级成功后执行维护脚本。观察新运行第一次已授权发送的 `dispatching` 阶段，强制退出 Server，并启动同一容器和同一镜像；不构建、不重建、不改变部署输入。轮询原运行直到租约恢复收敛为 `research_unknown_outcome`，attempt 与 request ID 保持不变，不能自动重新发送可能已产生费用的请求。发送授权状态不能证明远端实际接收或扣费，外部结果保留未知。

所有 SQL 只读；业务写入仅通过 Journal 正式 API 创建这一个测试运行。终态后再次核对账本、默认配置、旧报告与 Server/Worker 镜像。若没有进入故障窗口或存在其他在途任务，保留新运行/原因，不执行故障，不自动重复提交。故障后的恢复在 `finally` 中执行；恢复失败报告同一容器身份，不删除资源。
