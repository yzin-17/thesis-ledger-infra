# 回滚镜像数量保留机制规格

## 背景与目标

2026-10-05 只读排查确认，现有更新入口会把更新前镜像固定为 `rollback-<完整镜像 SHA>`，没有淘汰机制。六个历史回滚镜像的独占层合计约 6.59 GB。用户要求由本任务实施数量或期限淘汰机制，原聊天继续投资复盘与保数据升级。

本任务采用数量策略，默认每个服务保留两个历史回滚版本，防止镜像无限累计。只管理 `thesis-ledger` 与 `daily-stock-analysis` 两个仓库符合现有命名规则的回滚标签。无标签镜像、基础镜像、业务卷、日志、构建缓存和应用源码均不属于本任务清退范围。

## 保留与执行契约

1. `ROLLBACK_IMAGE_KEEP_COUNT` 默认 `2`，只能是大于零的安全整数；不提供清空所有历史版本的配置。按镜像创建时间从新到旧选择，时间相同时按完整镜像 ID 稳定排序。这里的时间是镜像构建时间，不冒充回滚标签首次创建时间。
2. 带当前开发标签或其他额外标签的镜像始终保护，不占仅含回滚标签的历史名额。任何现存容器（包括停止容器）引用的镜像、本次更新开始前固定的 Server/Worker/DSA 镜像、`ROLLBACK_PROTECTED_IMAGES` 指定的完整镜像 ID 或本仓回滚标签均保护。
3. 受保护的纯历史镜像计入数量名额；它们多于配置数量时允许超额，不淘汰保护对象，也不额外保留普通历史候选。Server 与 Worker 镜像不同仍分别保护；共享镜像按 ID 去重。
4. 更新前固定镜像时查询全部现存目标容器，覆盖停止状态及同服务多容器。非法镜像身份、标签冲突或查询失败立即停止固定流程，不把查询失败当作不存在。
5. 自动淘汰仅在 `prepare_database_for_update`、`start_updated_services` 与全部目标健康检查成功之后执行，与更新共用 daemon 互斥锁。更新失败不执行淘汰；清退失败输出独立警告，保留已完成更新的成功状态，不触发重建。
6. 提供仓库专用维护入口 `node scripts/rollback-image-policy.mjs [all|dsa|thesis-ledger]`，默认只读预览；只有 `--apply` 执行移除。应用模式共用更新锁并拒绝活动构建。借用锁时，锁文件 PID 必须匹配声明的更新进程，且该进程必须位于当前执行器的实际进程祖先链；兼容 Bash 3.2 临时环境赋值产生的中间子进程，不能只比较直接父 PID。祖先查询失败、循环、超出界限或无匹配时拒绝借用。自动调用只处理本次更新选中的仓库。
7. 只按计划移除精确回滚标签，使用 `--no-prune` 防止连带清退无标签父镜像，不使用 `--force`、批量 prune 或镜像 ID 删除。每个候选移除前重新检查容器引用、标签对应 ID、额外标签、数量计划与活动构建；变成保护对象就跳过。查询失败、身份变化或移除失败停止后续淘汰，已移除项与失败结果明确报告。
8. 配置、Docker 输出格式和镜像创建时间必须校验；错误时不得产生移除调用。显式保护引用无法解析时停止淘汰。所有 Docker 查询绑定同一个已核对的本地 context。

## 影响与边界

保留策略会改变成功更新后的历史镜像保留数量，不改变数据库升级、服务启动、构建空间门槛或故障恢复入口。额外标签与容器引用的保护可能使实际保留数超过目标，输出必须说明这一结果。共用锁只能协调仓库维护入口；其他外部进程仍可能并发修改 Docker，非强制精确移除与逐项复核提供最终保护，但不声明整个清退过程具有事务性。

首次实施只执行真实 Docker 只读预览。用户随后明确授权先删除回滚镜像，首次正式维护运行及其前后证据由当前任务单独记录。锁兼容修复不启动应用构建或更新，不要求原聊天另行实现。

## 验证策略与验收标准

- AC01：两个仓库独立保留最新历史版本；数量配置、稳定排序、共享镜像去重与保护超额行为有定向测试。
- AC02：停止容器、多个同服务容器、不同 Worker 镜像、本次更新前镜像、显式基线和额外标签均受保护；错误查询不能扩大淘汰范围。
- AC03：默认维护入口只读，应用模式共用更新锁、拒绝活动构建，并只执行非强制的精确标签移除；并发保护变化与部分失败可观察。
- AC04：自动调用位于更新及健康检查成功之后；构建、数据库或启动失败不调用淘汰，清退失败不重试已完成构建。
- AC05：现有固定回滚镜像、数据库、构建和兼容性回归保持通过，CI 纳入新增测试，文档与行为一致。
- AC06：用真实 Docker 只读预览核对候选和保护清单；实际删除、共享层释放及宿主磁盘回收不以模拟测试或预览代替。

## 风险与未决问题

数量默认值是本任务采用的可配置运维默认，不是用户要求的固定数量。保护优先可能使数量目标暂时无法满足，不能通过强制删除绕过。无阻塞设计问题；运行证据以正式维护入口的执行记录为准。
