# 策略编写目标进程恢复验收

实施与目标结果见[已完成任务](../archive/tasks/2026-10-06-authoring-target-recovery.md)。

## 范围与边界

固定 `desktop-linux`、`thesis-ledger-dev/thesis_ledger`。分别验收一个标记编写操作的 Server 故障、未派发补投和队列不可用拒绝。Server 故障期间数据库与 Redis 不停机；队列不可用阶段仅停止并恢复同一 Redis。使用与更新入口相同的互斥锁，禁止活动构建及其他在途研究、自动化、回测、编写任务，不改配置或重建镜像。

## 在途恢复

操作必须仍为 `running`、attempt 1、只有一个调用请求，最后调用事实为 `dispatching`。满足全部条件后，通过维护脚本对同一 Server 容器发送 SIGKILL 并启动。持久化租约过期后必须收敛为失败及外部结果未知；跨过两次调度周期仍保持一个调用和相同 attempt，禁止自动再次调用模型。用量未知不记为零。

BullMQ 基础设施锁为 180 秒。继续等待故障投递自然收敛，再核对数据库 attempt/调用事实，验证基础设施重领没有发起第二次模型请求；等待上限为 210 秒。不删除仍活动的投递。随后可通过主仓入口的 `--phase=delivery` 或 `--phase=outage` 独立执行后续阶段，已通过的实际故障证据保持。

## 未派发投递恢复

独立维护入口在无其他在途任务时暂停专用编写队列，通过正常 API 创建一个标记操作。确认数据库为 `queued`、attempt 0 且没有调用事实后，只删除该 UUID 对应且仍等待的队列投递，随后恢复队列。Server 成功查询缺失后必须有限补投并收敛终态，最终只有一个调用请求。不会改写业务状态或伪造 `not_sent`；队列查询失败的场景由隔离集成另行覆盖。所有异常路径恢复本入口暂停的队列并释放互斥锁。

补投阶段验证运输恢复、单一派发与持久化终态，独立于模型输出是否成功。实际派发后可成功、收到校验失败或因执行期限收敛为结果未知；未知终态必须失败、保留未知费用、只有一个调用且不再重发。真实生成成功由主仓 G2 纵向闭环单独证明。

## 数据保护与失败处理

注入前后核对账本、账户、历史策略/版本、模型配置、旧编写数据摘要。Worker、数据库、Redis 的容器和镜像保持。无论验收结果如何，脚本都恢复已停止的同一 Server；恢复健康后释放锁。发现目标、归属或并发条件不符，在 Docker 状态变更前退出。

## 队列不可用拒绝

独立维护入口确认无在途任务、固定数据库 owner、一个本次标记用户和四个健康容器后，停止同一 Redis，通过正常 API 提交分析。必须返回 `503/AUTHORING_UNAVAILABLE`，不得新增操作、调用或业务变化。恢复同一 Redis，等待 Server、Worker 与 Redis 健康，核对容器/镜像身份及 19 张保护表摘要。异常路径同样恢复 Redis 后释放锁。此阶段不删除 volume、不修改数据库、不改写队列数据。

## 验收层级

先运行参数、归属、故障窗口和恢复断言的定向测试，再执行真实目标。在途故障仅证明发送后的安全收敛；未派发补投和队列拒绝分别执行独立目标检查，取消另由隔离执行测试覆盖。不能从恢复终态推断外部模型实际收到或计费。
