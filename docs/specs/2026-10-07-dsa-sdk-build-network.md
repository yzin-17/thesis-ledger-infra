# DSA SDK 构建下载恢复

对应任务：[历史实施记录](../archive/tasks/2026-10-07-dsa-sdk-build-network.md)。本文保留为当前SDK下载与缓存维护契约。

## 目标与边界

公告用途修复镜像固化时，SDK 构建阶段直接使用 Debian HTTP 源，下载出现500／502，正式入口重试时同一软件包再次失败。运行镜像已有HTTPS镜像源、三次下载重试和45秒超时，但临时Dockerfile转换漏掉SDK的单行安装命令。

仅在infra的既有Dockerfile转换中，使SDK采用运行镜像相同的APT源、重试与超时；移除Docker自动清理APT下载缓存的配置，让已有SDK缓存挂载实际保留下载。保持SDK版本、补丁、基础镜像、安装包、Native验证、空间和服务更新门禁。

入口缓存整备后仍差少量Docker内部空间时，可用专用维护入口移除显式指定的失败构建记录。只接受精确记录ID，在共享更新锁下确认builder空闲并逐件核对状态为failed；不删除成功构建记录、镜像、容器、数据卷或业务文件。原失败日志已保留在宿主验收日志中。

DSA源码目录可再生成字节码缓存由独立维护入口预览／清理，仅限运行中的开发DSA及`/app/api`、`src`、`data_provider`、`bot`下面`__pycache__/*.pyc`。不遍历符号链接、不删除源码或其他文件，不进入data／logs／reports持久卷；复用共享更新锁与空闲builder检查。

## 验收

- AC01：SDK和运行镜像生成命令均使用现有HTTPS源与有界下载重试；SDK缓存不会被Docker自动清理，源Dockerfile保持不变。
- AC02：转换定向测试及语法验证通过；新的SDK单行命令结构不匹配时拒绝转换。
- AC03：通过正式`update.sh dsa`生成镜像，Native验证通过，主仓公告任务的镜像固化验收完成。当前旧配置构建的结果单独保留，不冒充新配置验证。
- AC04：失败记录维护入口拒绝空参数、非法ID、成功／未知状态和活动构建，只删除重新核对通过的显式失败记录，不使用全量删除或强制参数。
- AC05：字节码维护默认只预览，显式apply仅删除固定源码范围的pyc；符号链接、源码、其他文件和持久资料均保留。
