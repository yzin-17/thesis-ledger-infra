# 更新中复用已完成的 DSA 镜像

对应任务：[历史实施记录](../archive/tasks/2026-10-07-update-resume-built-image.md)。本文保留为当前入口契约。

## 目标与契约

正式全栈更新已经成功构建 DSA，随后因 Server 构建前空间不足停止时，可以在源码未再变化的前提下复用该已完成的不可变镜像。操作仍从 `update.sh` 进入，保留空间、并发、数据库、镜像保留与启动健康门禁。

新增可选 `REUSE_DSA_IMAGE_ID`，取上一次正式更新输出的完整 SHA256 镜像 ID，默认不设置。设置时必须选择 `all` 或 `dsa`；核对当前 DSA 开发标签与指定 ID 完全相等，服务标签为 `dsa`、契约标签为 `1`。验证在入口与跳过构建前各执行一次；任意不匹配立即停止。未知、历史或源码已经变化的镜像不属于该参数的使用范围。

脚本启动时集中整备并检查空间一次，宿主达到20GiB、Docker达到18GiB后才开始。后续各镜像构建不重复预检；实际ENOSPC仍按既有有界故障恢复处理。只跳过 DSA 的重复构建，完成产物保护、服务更新和健康检查保持；Server仍按原入口构建。

## 验收

- AC01：完整 ID、当前标签、服务／契约均匹配时复用；非法 ID、身份错配或标签变化拒绝。
- AC02：默认仍构建所有选中服务；复用时只跳过 DSA，保留入口单次空间检查与镜像保护，Server仍构建。
- AC03：原空间／并发／数据库编排测试通过；真实全栈恢复在至少20GiB门禁下启动并验证服务。
