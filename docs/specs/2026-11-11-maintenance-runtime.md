# 维护运行层与恢复职责

日期：2026-11-11。[已完成任务](../archive/tasks/2026-11-11-maintenance-runtime.md)。[验收证据](../archive/evidence/2026-11-11-maintenance-runtime.md)。

## 目标

维护脚本共用本地 Docker context、进程执行和锁实现；同步的二进制备份与异步部署共用校验规则，保留各操作明确的输出、超时与取消契约。研究恢复演练协议、回执和业务数据库处理由应用维护。

## 验收标准

- AC1：研究恢复演练、F01 回执与资源归属判断迁回 ThesisLedger；SQLite 恢复由 DSA 维护。infra 不保留内嵌 Python，现有备份格式、路径保护、隔离网络、归档拒绝链接和越界、SQLite 完整性保持。
- AC2：更新、镜像维护、既有容器启动共用一套锁创建/释放与祖先判断。归属改变时保留锁并失败，借用锁必须匹配真实祖先；异步执行完成前不释放锁。
- AC3：Docker 操作通过共用运行层固定本地 Unix context，拒绝端点覆盖；进程层统一 argv、环境、错误与输出处理，显式支持二进制、文件描述符输出及操作超时。恢复及备份调用者同步更新。
- AC4：容量模块直接提供实现，CLI 路由单向调用；保留现有 7 个部署入口和参数。删除无调用的路径函数，旧重复实现及调用引用清零。
- AC5：按定向测试、包级测试、门禁、真实只读/幂等维护和正式快更逐层验证。保持数据、挂载、镜像及服务健康；不执行共享恢复故障注入、扩容、清库、业务外部调用或 Git 提交/推送。应用镜像输入未变时不重复构建。

同步与异步是进程适配形式，不再各自定义 context 与锁策略。业务应用的语言由应用负责，infra 不代持业务恢复程序。
